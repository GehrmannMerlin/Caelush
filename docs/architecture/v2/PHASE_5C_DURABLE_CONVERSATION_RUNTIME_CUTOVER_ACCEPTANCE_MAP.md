## 2. Cross-layer ownership rules

1. `@caelush/agent` owns the stable RunExecutionStore contract and the message semantic/factory/codec
   contracts. It does not import Storage or SQLite.
2. `@caelush/core` owns lifecycle orchestration and the message materialization bridge. It may request
   factory/codec/projector behavior through narrow injected ports, but it never opens a database.
3. `@caelush/storage` owns only raw V2 record persistence and the existing atomic SQLite transaction.
   It must not import `toAgentAIMessage`, semantic decode, or a projector registry.
4. `apps/daemon` is the only production composition root. It creates one canonical factory, codec
   registry, projector registry, and message authority and passes them into Core.
5. The compatibility projection is a 5C runtime seam, not a second durable authority. No durable
   AIMessage/LLMMessage append is accepted after this cutover.

## 3. Fault and recovery matrix

| Boundary                                            | Required result                                                                                  |
| --------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| User factory/encode before Run commit               | No DB/provider side effect if preparation fails; Run remains recoverable                         |
| User commit succeeds, process stops before provider | Recovery finds the durable USER by identity and does not append another one                      |
| User transaction fails                              | Run/State/message/event changes roll back together; provider is not called                       |
| Assistant materialization or encode fails           | No Step/Run/State/Continuation/event or assistant message is committed                           |
| Assistant transaction fails                         | No partial assistant message; the same provider result is not silently re-sent                   |
| Observation committed, ToolResult absent            | Recovery projects the same bounded feedback under the persisted policy snapshot and appends once |
| ToolResult already committed                        | Recovery reuses the committed identity and does not duplicate it                                 |
| Unknown visible message schema/projection           | Fail closed before provider invocation; never silently fall back to legacy AI history            |
| V2 sequence conflict                                | Surface a storage conflict; never preallocate or repair message sequence in Core                 |

## 4. Phase 5C exit / Phase 5D holdbacks

The following remain intentionally out of this round:

- ContextEngine, Replay and AgentLoop public inputs remain AI-compatible projections.
- Legacy physical columns, legacy repositories and legacy backfill compatibility remain in place.
- No full conversation replay redesign, transcript/client migration, permission/approval, retry,
  budget, timeout, cancellation, verification or completion architecture changes are introduced.

Phase 5C exits only when the acceptance tests prove that all new USER, ASSISTANT and TOOL_RESULT
messages are Factory -> Codec Registry -> `AgentMessageRecordDraft` -> RunExecutionStore -> V2 rows,
and the full verification/reporting checklist is recorded.
